# GPU Guide — sm_120 (Blackwell)

Cards: RTX 5090, RTX 5080, RTX 5070 Ti / 5070, RTX 5060 Ti / 5060

## Capabilities

| Feature              | Value                                    |
|----------------------|------------------------------------------|
| Compute capability   | 12.0                                     |
| Tensor cores         | 5th-gen: FP4, FP6, FP8, FP16, BF16, INT8, INT4 |
| MMA shape (FP16)     | m16n8k16                                 |
| MMA shape (INT8)     | m16n8k32                                 |
| MMA shape (FP8/FP6/FP4) | m16n8k32 with `.kind::f8f6f4`         |
| Shared memory / SM   | 100 KB (99 KB usable per block)          |
| L2 cache (5090)      | ~96 MB                                   |
| L2 cache (5080)      | ~72 MB                                   |
| Registers / SM       | 64K × 32-bit                             |
| Warp size            | 32 threads                               |
| Max threads / block  | 1024                                     |
| Block cluster (max)  | 8 blocks                                 |
| Memory bandwidth     | ~1792 GB/s (5090), ~960 GB/s (5080)      |

## sm_120 is not sm_100

Consumer Blackwell (compute capability 12.0) is a different design from
datacenter Blackwell (10.0). Two differences matter for kernels:

- **No Tensor Memory and no `tcgen05` UMMA.** Tensor Memory is sm_100-only.
  On sm_120 use the classic `mma` / `wmma` path — the same shape as Ada.
- **FP4 / FP6 `mma.sync` needs the arch-specific target.** The `.kind::f8f6f4`
  variants require `-arch=sm_120a` (CUDA 12.9+). Build plain `sm_120` unless
  you actually use FP4/FP6, otherwise the binary is unnecessarily restricted.

## What this means for inference kernels

**FP4 is the headline.** 5th-gen tensor cores add FP4 (and FP6), roughly
halving weight bytes versus FP8. Q4-class GGUFs can be dequantized straight
to FP4 tiles instead of FP16, cutting shared-memory traffic. This is the
biggest win on Blackwell and the reason a tuned sm_120 kernel beats an Ada
kernel ported 1:1.

**Attention is memory-bandwidth bound at batch=1.**  
At a single token you read O(ctx_len) K/V. The 5090's ~1.8 TB/s is the
ceiling. ~96 MB of L2 fits all K/V for a long context at FP16 — tile your
K/V reads to stay resident.

**FFN is compute-bound.**  
Use INT8 (`m16n8k32`) for Q8_0 weights, or dequant Q4_K to FP4 and use the
FP4 path. On sm_120 the FP4 path is where the extra throughput lives.

**Good tile sizes to start with (tune from here):**

```
FFN matmul (Q4_K→FP4): BLOCK_M=128, BLOCK_N=128, BLOCK_K=64, pipeline_stages=3
Attention QK^T:        BLOCK_Q=64,  BLOCK_K=64,  BLOCK_V=64
RMS norm:              one warp per row for hidden_dim=4096 (128 threads)
```

## Known-fast patterns

- **Prefer FP4 for Q4-class weights.** Dequantize Q4_K blocks into FP4 tiles
  rather than FP16; the tensor cores consume them directly.
- **Thread block clusters** (up to 8 blocks) can share L2 residency across
  blocks — useful for tiling attention K/V that all blocks read.
- **Warp-level reduce for rms_norm**: `__shfl_xor_sync`, same as Ada.
- **Prefetch the next K/V tile while computing the current one**: the large
  L2 makes a 2-stage pipeline effective at ctx_len > 1024.

## Common mistakes

- **Using `tcgen05` / Tensor Memory intrinsics.** They do not exist on
  sm_120; the build will fail or fall back. Use `mma` / `wmma`.
- **Targeting `sm_120a` when you don't use FP4/FP6.** It restricts the binary
  to arch-specific features for no benefit.
- **Assuming sm_89 tile sizes are optimal.** FP4 changes the arithmetic
  intensity; retune K and the pipeline depth.
- **Not handling non-multiple-of-tile dimensions.** An 8B model with
  ffn_dim=14336 divides cleanly (14336 / 128 = 112). Always add a bounds
  check; other models may not divide evenly.
