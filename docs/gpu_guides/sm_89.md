# GPU Guide — sm_89 (Ada Lovelace)

Cards: RTX 4090, RTX 4080, RTX 4070 Ti/Super/regular, RTX 4060 Ti/regular,
       RTX 4000/5000/6000 Ada (workstation)

## Capabilities

| Feature              | Value                                    |
|----------------------|------------------------------------------|
| Compute capability   | 8.9                                      |
| Tensor cores         | FP8, FP16, BF16, INT8, INT4              |
| MMA shape (FP16)     | m16n8k16                                 |
| MMA shape (INT8)     | m16n8k32                                 |
| MMA shape (FP8)      | m16n8k32                                 |
| Shared memory / SM   | 100 KB (99 KB usable with max occupancy) |
| L2 cache (4090)      | 72 MB                                    |
| L2 cache (4070)      | 36 MB                                    |
| Registers / SM       | 65536 × 32-bit                           |
| Warp size            | 32 threads                               |
| Max threads / block  | 1024                                     |
| FP16 TFLOPS (4090)   | 165.2                                    |
| Memory bandwidth     | 1008 GB/s (4090), 504 GB/s (4070)        |

## What this means for inference kernels

**Attention is memory-bandwidth bound at batch=1.**  
At a single token, you're doing O(ctx_len) reads for K/V. The 4090's 1 TB/s
bandwidth is the ceiling. Tile your K/V reads to hit L2 cache — 72 MB fits
all K/V for a 4k context llama3-8b at FP16.

**FFN is compute-bound.**  
The gate/up/down matmuls are large. Use INT8 tensor cores (m16n8k32) for
Q8_0 weights, or dequant Q4_K to INT8 on the fly and use the same path.
FP8 tensor cores are available but FP8 quant isn't a common GGUF format yet.

**Good tile sizes to start with (tune from here):**

```
FFN matmul (Q4_K):   BLOCK_M=128, BLOCK_N=128, BLOCK_K=64, pipeline_stages=3
Attention QK^T:      BLOCK_Q=64,  BLOCK_K=64,  BLOCK_V=64
RMS norm:            one warp per row for hidden_dim=4096 (128 threads, 32 per warp)
```

## Known-fast patterns

- **Warp-level reduce for rms_norm**: `__shfl_xor_sync` is fast on Ada.
  Four shuffles to reduce 32 values. For hidden_dim=4096 with 128 threads:
  each thread holds 32 values, reduce within warp, then across warps via
  shared memory.

- **Prefetch next K/V tile while computing current one**: Ada's L2 is large
  enough that a 2-stage pipeline (ldgsts + mma) reduces memory latency
  significantly at ctx_len > 1024.

- **INT8 tensor core path for Q8_0**: load weight bytes directly as INT8,
  scale after the mma. No intermediate float conversion needed.

## Common mistakes

- **Using `__syncthreads()` unnecessarily**: adds ~5 µs per layer. Only sync
  when you actually need shared memory to be visible across warps.
- **Occupancy too low**: if you use 100 KB of shared memory your occupancy is
  1 block/SM. Try to stay under 50 KB to get 2 blocks and hide latency.
- **Not handling non-multiple-of-tile dimensions**: llama3-8b ffn_dim=14336.
  14336 / 128 = 112 exactly. llama3-70b has 28672 — also divisible. But
  always add a bounds check; other models may not divide evenly.
